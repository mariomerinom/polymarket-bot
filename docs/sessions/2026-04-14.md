## What We Learned

- **WAL race condition was silently corrupting DBs.** `_git_commit_push()` ran `git add data/` while the engine held active WAL journals. Git snapshotted incomplete `.db` files (unflushed WAL pages) + committed transient `.db-wal/.db-shm` files. Result: `predictions.db`, `predictions_kalshi.db`, and `predictions_bybit.db` each lost ~24h of data.
- **Belt-and-suspenders fix matters.** Three layers added: (1) checkpoint before add, (2) gitignore WAL/SHM, (3) `git rm --cached` WAL/SHM after add. Each layer catches a different failure mode.
- **The fix is now in the engine loop.** `_checkpoint_all_dbs()` runs before every auto-commit cycle, not just at startup. This makes recovery automatic regardless of how the engine restarts.
