## What We Learned

- **Cross-symbol resolution is a data corruption vector.** `_auto_resolve()` resolved ALL pending predictions regardless of symbol — BTCUSDT candle close was resolving ETHUSDT/SOLUSDT/DOGEUSDT predictions using BTC's direction. 1,600 predictions corrupted before catching it.
- **Historical data poisons analysis.** The HV/N gate (added Apr 9) looked like it wasn't working because MCP returned historical pre-gate data mixed with post-gate data. Always check WHEN data was generated.
- **Kalshi correlation structure:** One wrong BTC direction call wipes an entire batch of "Will BTC be above $X?" markets simultaneously. 0% WR on 40 bets in one day was structural, not a bug.
- **Always-fire > selective for parameter optimization.** Hard thresholds bake in assumptions. Log everything, optimize post-hoc. The metadata IS the strategy.
- **VPS memory leak:** Engine grows ~50MB/hour. Zombie process from previous restart (PID 128641) found consuming 165MB. Mitigated with daily 4am UTC cron restart.
- **HV/N gate P&L model:** Filtering ~101 coin-flip bets saves only ~$26 in P&L but meaningfully reduces variance. Value is risk reduction, not profit increase.
